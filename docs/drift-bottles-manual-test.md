# 漂流瓶完整手动验收流程

适用于带有“内容管理 → 漂流瓶”标签的功能分支。按顺序完成用户流程、审核、异常与权限测试，最后执行结束、举报和屏蔽。每项勾选表示已观察到预期结果；未执行的项目保持未勾选，并标记“未测”或“环境阻塞”。

## 测试入口与准备

当前测试站：<https://sb-47n2f9pzxumy.vercel.run>。仅在该隔离测试站操作。

| 用途 | 路径 |
| --- | --- |
| 登录 | `/login` |
| 漂流瓶 | `/drift`，或探索菜单 → 漂流瓶 |
| 我的瓶子 | `/drift?tab=bottles` |
| 内容审核 | `/admin?tab=drift`，或内容管理 → 漂流瓶 |
| 旧审核入口兼容 | `/admin/drift`，应跳转到上述标签 |
| 指定瓶子 | `/drift?bottle=实际瓶子ID` |

准备相互隔离的浏览器会话。同一浏览器的多个普通标签通常共用登录 Cookie；多个无痕窗口也可能共用会话，优先用不同浏览器或不同浏览器配置。

| 身份 | 测试账号 | 用途 |
| --- | --- | --- |
| A | `drift-a` | 投瓶、接收回信 |
| B | `drift-b` | 捡瓶、寄出回信 |
| R | `drift-reviewer`，角色 `admin` | 审核与权限验证 |
| C | 额外普通测试账号，需事先由测试环境维护者准备 | 非参与者权限、竞争领取；不能用管理员替代此角色 |
| G | 未登录的独立会话 | 访客权限 |

密码使用本次测试环境已提供的凭据，不写入仓库。C 未准备时，其专属用例记为“环境阻塞”；A、B、R 可先完成主要流程。

每轮使用唯一前缀，例如 `MT1025-01`，每条内容再加用例编号。记录瓶子 ID、回信 ID 与参与账号；不要仅凭文本判断是否同一个瓶子。

当前沙箱单次运行 45 分钟，快照保留设置为一天。整套测试应分轮进行，超时后由维护者恢复并启动服务；不要把暂时停机记为数据丢失。更新前端后需要重启 Node 服务，再确认实际页面显示五个管理标签。

### 执行顺序与数据安排

1. 第一轮执行入口、投捡瓶、回信与草稿。
2. 第二轮执行瓶子审核、回信审核和管理页操作。
3. 第三轮执行权限、输入边界、断网、手机与多语言。
4. 按条件执行翻译、大数据量与并发测试。
5. 使用新瓶子分别执行结束、举报；最后执行屏蔽。

准备独立瓶子：普通通信瓶 P1、放回测试瓶 P2、结束测试瓶 P3、举报通过瓶 P4、举报拒绝瓶 P5、屏蔽测试瓶 P6。不要在同一瓶子上依次执行所有破坏性操作。

投瓶、回信、举报共用每账号每 10 分钟 12 次的限流；捡瓶、扔回海里共用每账号每 10 分钟 30 次的限流。失败请求也可能占次数。出现 429 时记录 `Retry-After`，等待后再测；限流专项放在最后，避免干扰其他用例。

随机池有旧瓶子时可能捡到其他内容：未回信的瓶子可放回，或记录实际取得的 ID。证明某个待审瓶子不可领取，需要结合其 ID 和权限检查；连续几次没捡到不能单独作为充分证据。不要为测试清空其他人的已有内容。

## 附录 在浏览器中复核接口

仅在测试站、对应角色已登录的会话中打开开发者工具 Console。以下辅助函数使用当前 Cookie，不需要复制令牌或密码；检查状态码和返回正文，不能只看 UI 提示。

```js
async function driftCheck(path, method = 'GET', data) {
  if (!/^\/api\/(?:drift|moderation\/drift)(?:\/|$)/.test(path)) {
    throw new Error('仅允许本清单中的漂流瓶接口');
  }
  const response = await fetch(path, {
    method,
    credentials: 'same-origin',
    headers: {
      'Content-Type': 'application/json',
      'X-Requested-With': 'XMLHttpRequest'
    },
    ...(data === undefined ? {} : { body: JSON.stringify(data) })
  });
  const body = await response.json();
  console.log(response.status, body);
  return { status: response.status, body };
}
```

- **A01 超长拒绝**：A 执行 `await driftCheck('/api/drift', 'POST', { content: '字'.repeat(2001) })`；应为 422，没有新增瓶子。这样可以复核输入框截断以外的服务端校验。
- **A02 非参与者越权**：C 用实际 ID 执行 `await driftCheck('/api/drift/123')`，应 404；再分别向 `/api/drift/123/replies`、`/close`、`/block`、`/report`、`/return` 发 POST，均不得成功。回信需正文 `{ content: '越权测试' }`；其他操作使用 `{}`。实际 ID 必须属于 A/B，不能用不存在的 ID 代替权限测试。
- **A03 放回限制**：当前领取者对已有任意回信的瓶子执行 `await driftCheck('/api/drift/123/return', 'POST', {})`，应为 409；待审、已拒回信均计入“已经通信”。作者或第三人请求不能成功。
- **A04 审核竞争**：R 在两个会话对同一个待审瓶子执行 `await driftCheck('/api/moderation/drift/bottles/123', 'POST', { status: 'approved' })`；首次 200，再次为 409。回信用 `/replies/实际回信ID`，不是瓶子 ID。
- **A06 重试去重**：同一账号生成 `const requestId = crypto.randomUUID()`；向投瓶或某瓶回信接口连续发送完全相同的 `{ requestId, content: '重试验收', language: 'zh' }`，应返回相同回执，实际只存一条且通知不增加；同一标识更换正文/语言/所属瓶子应 409。仅不带标识的旧客户端不保证去重。
- **A05 无权限审核**：A/C POST 上述审核路径，应为 403；R 提交非法状态（例如 `{ status: 'pending' }`）应为 400，条目不应改变。

以上均使用测试数据。失败请求也可能占用限流额度。不要为了“重测”再次审核其他人的真实内容。
