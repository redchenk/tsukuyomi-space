# 支付宝支付与订单接入

提供商品配置、下单、电脑网站支付收银台、RSA2 异步通知验签、主动查单和订单管理。勾选“支付成功后充值到网站余额”的商品，在验签后按订单实付金额自动入账；普通商品仍按说明交付。主站与 official-api 共用这份余额，不自动开通会员，不自动退款；浏览器跳转参数不能作为入账依据。

## 网站统一余额

迁移 `046_create_site_wallet` 在主站数据库增加整数精度的钱包、预留和结算账本。1 元为 1,000,000,000 金额单位，按完整请求一次向上取整。订单建立时保存充值金额快照，之后改价或取消充值标记不会改变旧订单。验签记为已支付与充值入账在同一数据库事务中完成；同一订单多次通知或查单只入账一次。生产钱包不会接收沙箱订单。

用户统一在 `/payments`「支付中心」查看网站余额、冻结金额、支付宝充值与订单、站内直供模型价格、最近请求明细与 UTC 月账单。Room 设置只链接此页；生产 `/official-api` 和 `/official-api/` 旧页面通过 308 跳转（保留合法订单编号），插件 API、Webhook 和健康检查地址不变。维护者可在同页展开「直供服务管理」，供应商密钥只写不读，充值商品仍在现有 Terminal 支付管理中配置。独立插件故障不会阻止主站余额和订单读取。站长在 Terminal → 支付与订单配置商品价格和充值标记。经主站核验的 super-admin 可免扣费使用官方模型，仍记录用量；普通账号先预留主站余额，取得最终用量后扣费并释放多余冻结。未知结果保留冻结，不按超时退款。

独立插件通过固定环回接口 `/api/internal/official-wallet` 调用主站；需要服务端专用 32 字节 HMAC 密钥文件（主站 `OFFICIAL_WALLET_KEY_PATH`、插件 `SITE_WALLET_KEY_PATH`），不复用支付宝密钥或 JWT 密钥。接口校验请求签名、60 秒时间窗、单次 nonce，拒绝浏览器 Origin、Bearer 和非环回连接。预留还必须携带当前主站 Cookie，并重新校验真实用户与 super-admin 权限。结算按主站锁定的价格和模式计算，不能传任意扣费金额；持久化请求编号防止重试重复扣费。密钥不得提交仓库或返回前端。

历史订单不会自动当作充值。经维护者确认“尚未发放”的额度商品，可用 `node scripts/backfill-wallet-topups.js 商品编号...` 先核对，再加 `--apply` 执行一次性补入；按历史订单实付金额和原订单号入账，可安全重跑。先备份主站数据库，不回填普通商品，不覆盖已有余额。

## 开启前的服务器配置

安装根目录依赖（`npm ci`），重启后自动执行迁移 `045_create_payment_orders`。新安装和升级均默认关闭收款，商品列表为空。现有聊天、成长积分和 AI 设置保持原有行为。

实际 AppID、商户 PID、应用私钥及支付宝公钥由服务器环境变量或私有文件提供。仓库中的 `.env.example` 和 `.env.docker.example` 只包含空值，代码没有当前账号的任何密钥或标识，也不会自动读取开发者的下载目录。

| 变量 | 用途 |
| --- | --- |
| `ALIPAY_ENV` | `production`（默认）或 `sandbox`；固定使用对应的支付宝官方网关，不能指定任意网关 |
| `ALIPAY_APP_ID` | 自己的支付宝应用 AppID，必须是 16 位数字 |
| `ALIPAY_SELLER_ID` | 实际收款商户的 PID，必须是 16 位数字，与签约主体一致 |
| `ALIPAY_PRIVATE_KEY_PATH` | 应用私钥文件的绝对路径；支持 PKCS#1 / PKCS#8 和官方工具导出的纯 Base64 |
| `ALIPAY_PUBLIC_KEY_PATH` | 支付宝公钥文件的绝对路径；支持 PEM 或官方导出的纯 Base64 文本 |
| `PAYMENT_PUBLIC_BASE_URL` | 接收通知的公网网站 origin，例如 `https://pay.example.com`，生产必须 HTTPS，不能包含额外路径、查询参数或凭据 |
| `PAYMENT_MAX_ORDER_YUAN` | 服务器单笔金额上限，默认 `50` 元；应不高于商户实际可收款限额 |

也可以用密钥管理系统注入 `ALIPAY_PRIVATE_KEY`、`ALIPAY_PUBLIC_KEY`，文件路径优先。私钥只用于服务器签名，不交给浏览器。支付宝公钥与应用公钥是两把不同的公钥，不能混用。服务启动器须将环境变量传给 Node 进程；本项目不会自动加载任意 `.env` 文件。

推荐将私钥放在仓库外的服务器专用目录，目录权限 `700`，文件 `600`，仅运行 API 的用户可读。Docker 可用服务器私有 Compose override / secrets，将文件只读挂载至 `/run/secrets/`，并把上述路径指向容器内文件；不要 COPY 密钥到镜像或提交本机绝对路径。生产勿开启 `NODE_DEBUG=alipay-sdk*`，SDK 调试日志会包含请求与签名资料。

1. 在支付宝开放平台完成接口加签、应用上线，以及“电脑网站支付”签约。沙箱使用独立的沙箱 AppID、密钥和商户 PID。
2. 配置服务器变量并重启 API。进入 **Terminal → 支付与订单**，只有超级管理员可查看和修改此面板。页面展示配置就绪状态和缺失的变量名，不返回实际密钥、AppID 或 PID。
3. 添加商品：填写稳定的商品编号、名称、价格（元）、交付说明，勾选上架，再勾选“开启在线收款”并保存。未就绪或没有可售商品时无法开启。未保存的商品编辑不会影响在售配置。
4. 用户从用户中心的“支付与订单”进入 `/payments`。购买时必须登录个人站点账号；订单归属于当前账号，服务端确定金额。关闭收款后，有历史订单的用户仍保留入口。

## 回调与订单状态

异步通知地址固定为 `${PAYMENT_PUBLIC_BASE_URL}/api/payments/alipay/notify`，由下单请求携带。回跳地址为 `${PAYMENT_PUBLIC_BASE_URL}/payments?order=订单号`。开发设置中的“应用网关”和“授权回调地址”与此支付通知不是同一个概念，无需为通过检测随意填写不存在的接口。

反向代理/CDN 应允许支付宝对通知地址发送 `application/x-www-form-urlencoded` POST，不缓存、不加网页登录或 JS 人机挑战，不重写表单内容。仅此精确 POST 路径使用 RSA2 校验替代浏览器 CSRF；其他 API 的认证、Origin 和写入保护仍生效。请同时确保 `/api/payments/*` 和 `/api/admin/payments/*` 不被缓存，页面路由 `/payments` 可回落到前端 SPA。

- 下单仅接受商品编号和幂等请求编号，不接受客户端金额、账号 ID 或交付额度。订单金额和商品名称保存快照，之后调价不会修改旧订单。
- 一个请求编号对同一用户只创建一个订单；重复通知、查单和乱序通知不会重复记录成功。支付宝交易号全局唯一，不能用于多个订单。
- 通知必须通过 RSA2 验签，并匹配订单号、AppID、收款 PID、金额和交易号。只有 `TRADE_SUCCESS` / `TRADE_FINISHED` 才记为已支付。
- 同步回跳只触发服务器主动查单，不信任 URL 中的成功参数。查单使用官方 SDK 并启用响应验签，金额或订单不匹配时不入账；错误日志与 API 不回显 SDK 原始响应。
- 订单付款有效期约 15 分钟。到期仅停止打开收银台；页面会提示“已到期，待确认”，需要通知或查单核对状态。即使订单已关闭，后续合法的成功结果仍能纠正为已支付。已支付订单不会被较早的关闭通知降级。
- 关闭开关只停止新建订单及新打开收银台；已经生成的支付宝付款链接在自身有效期内仍可能付款，已有订单继续接收合法通知和查单。
- 正式与沙箱订单互相隔离。更换 AppID、PID 或环境前，先处理已有待付订单；配置身份改变后旧订单不会错误地用新身份入账。密钥轮换应与支付宝平台同步完成。
- 退款或退单需要到支付宝商家平台核对与处理。本版本的 `paid` 表示曾确认支付成功，不自动跟踪后续退款状态，也不会撤销任何站内权益。不能用本版本作为自动交付或自动退款系统。

## 验证与上线

运行 `npm run test:payments` 和 `npm run build:web`。测试使用临时数据库与运行时生成的 RSA 密钥，包含真实签名验证、伪造/错额/错商户通知、重复通知、越权订单、配置缺失、开关关闭及官方 SDK 查单验签；不会接触生产资金或账号。

生产开启前，先完成支付宝沙箱的下单、付款、异步通知和查单验证，再由站长授权做一笔真实小额订单。检查金额、归属、重复通知与关闭开关后的结算。单元测试和本地构建不代表生产代理、平台审核或真实到账已验收。

回滚时先在 Terminal 关闭新收款，继续保留通知处理、配置和数据库以结算已有订单。不要删除订单表；订单记录在用户注销后保留，账号归属字段置空。

官方参考：[Node SDK](https://github.com/alipay/alipay-sdk-nodejs-all)、[电脑网站支付](https://open.alipay.com/api/detail?code=I1080300001000041203)。本实现沿用电脑网站支付的 V2 `pageExecute` 和 `exec` 查单协议，明确启用 RSA2 及响应验签；未申请手机网站支付签约，不调用 WAP 或 App 支付产品。
