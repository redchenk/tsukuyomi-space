## 体验与社交关系

登录用户可以自由投瓶、随机捡瓶、再投一个瓶子或在已捡到的瓶子内私密回信。
不设每日题目、开头/结尾配对、每日两题、积分奖励或视觉生成。
每个瓶子只交给一个其他用户，SQLite immediate 事务中领取，不能捡自己的瓶子。
自己的瓶子、领取的瓶子按 ID 翻页，每页 30 条；对话显示最近 100 条可见回信。

月读已有关注、个人主页、公开留言/回复和站内通知；没有独立的一对一私信或
双向好友申请表。因此首版使用瓶内私密回信作为交流通道，主页和关注沿用
`/users/:username`、`/api/user/follow/:id`。互相关注继续沿用原有数据，
没有另建好友系统，也没有将私密回信写进公开留言、公开动态或 RSS。
回信通知只写通用标题和瓶子链接，不携带私密正文，避免把正文带入通知下游。

参与者可结束对话、屏蔽对方或举报。屏蔽双向阻止新回信和之后的随机匹配，
已有历史仍可回看。举报关闭并隔离整个瓶子，进入管理员待审队列；审核通过
也不会自动重开这段对话。首版没有自助解除屏蔽入口。

## 审核与权限

瓶子及所有回信直接调用 `reviewMessageContent`，与广场共用关键词配置、
外链识别、危险协议/活动标记拒绝、2000 字符与 8000 字节限制。
不接入 Claude 或任何其他大模型，不新增 API Key 或按次模型费用。
普通文本立即通过，关键词与站外链接进入人工待审。
审核结果快照保存在独立表中，不混入公开留言。

待审/拒绝内容仅作者和有内容审核权限的管理员可读。瓶子通过审核并被领取后，
才向领取者开放正文；回信通过审核后才向另一方开放。
普通账号不能枚举或读取别人的瓶子、回信和审核队列。
管理员可通过或拒绝待审项，重复审核返回 409。
人工审核界面显示原文、规则快照或举报来源；管理员应核实站外链接。

使用现有 Cookie 鉴权、可信写入来源检查、重复 JSON 键拒绝和 API 总限流。
漂流瓶写入限制每账号每 10 分钟 12 次，领取限制每账号每 10 分钟 30 次。
请求体限制为 16 KiB，审核操作为 4 KiB；响应继承 private/no-store。
迁移 `055_create_drift_bottles`、`056_create_drift_submissions` 在启动时自动执行；账号删除通过外键级联清理。
上线前备份数据库。回滚应用时保留新增表，避免丢失历史。

## 跨服与翻译

海外站现有 `/api/` 代理连接国内同一 API 与数据库，投瓶和随机池共用。
`/api/drift` 不加入 `/en-api` 或 `/api/live` 的公开读路由，领取、列表和私信
始终携带登录 Cookie，避免公开翻译代理丢失用户身份或缓存正文。

界面支持中文、日文、英文。内容保留原文及提交时界面语言（不是语言检测）。
英文界面提供主动“Translate to English”，复用现有海外站本地 Argos 翻译，
不使用付费模型。请求通过 `/en-translate-private` 转发到现有服务的 `/translate/private`，只发送
当前用户已获权读取的瓶子和回信；服务器既不读取也不写入共享翻译缓存。
翻译文本只留在当前页面内存，不替换原文，也不参与审核判定。

**部署时同步更新并重启翻译服务，加载新版 `deploy/overseas-openresty.conf`**。
使用独立路径确保旧服务不支持时返回 404，不会退回公共翻译缓存。
国内本地开发环境没有该服务时可以阅读原文；翻译失败不会阻断回信。
本次沿用现有中/日→英翻译方向，没有新增英→中或中→日翻译服务。

## 人工验收：两账号、一位审核员

### 独立测试站布置

仓库提供 **独立** Compose 文件，不与正式 `docker-compose.yml` 合并：
它使用自己的项目名、镜像标签、数据库卷、上传卷及回环端口 3290，
并关闭 SMTP、Redis、云端 LLM 与第三方登录。不要复制正式环境文件、数据库
或对象存储配置。不要把 `tests/e2e-server.cjs` 的测试专用接口暴露到公网。

在测试机的独立检出目录执行：

```bash
cp .env.drift-test.example .env.drift-test.local
# 编辑 .env.drift-test.local：独立测试域名、Cookie 域、JWT 密钥和审核员密码。
# 可用 openssl rand -hex 32 生成独立 JWT 密钥。
docker compose -f docker-compose.drift-test.yml up -d --build
curl http://127.0.0.1:3290/api/health
```

在现有 Nginx/OpenResty 增加测试域名的 HTTPS 虚拟主机，将 `/` 代理到
`http://127.0.0.1:3290`，传递 Host、X-Forwarded-Proto 和真实客户端 IP。
只允许测试人员访问（现有 VPN、IP 白名单或网关访问控制均可）。
测试域名不要与正式站共用父域 Cookie；示例中 Cookie 为测试域专用。

为了不依赖注册邮件，启动成功后创建两个普通账号。密码由操作者现场输入，
脚本不输出密码，也不覆盖已经存在的账号：

```bash
read -rsp 'Test account password (12+ characters): ' DRIFT_TEST_PASSWORD
export DRIFT_TEST_PASSWORD
docker compose -f docker-compose.drift-test.yml exec --env DRIFT_TEST_PASSWORD web node scripts/create-drift-test-users.cjs
unset DRIFT_TEST_PASSWORD
```

账号 A 为 `drift-a`，账号 B 为 `drift-b`；都使用刚输入的测试密码。
审核员用 `.env.drift-test.local` 配置的账号在 `/login` 登录，再进入
内容管理页 `/admin`，点击“漂流瓶”标签（可直达 `/admin?tab=drift`），无需进入超级管理员 Terminal。旧链接 `/admin/drift` 会跳转到此标签。

### 手工测试清单

用两个不同浏览器或一个普通窗口加一个无痕窗口分别登录 A、B。
审核员最好用第三个浏览器配置，避免覆盖 A/B 的登录 Cookie。
从空的测试瓶子池开始，每一步使用带时间戳的文本以便辨认。

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1 | A 投普通文本，如“今夜一起看月亮 001” | 状态已通过；A 自己捡不到这个瓶子 |
| 2 | B 点击捡瓶 | 取得 A 的瓶子和原文；再刷新仍能从“我的漂流瓶”打开 |
| 3 | B 寄出普通回信；A 刷新通知后打开 | 通知链接指向该瓶子，A 能看见回信并回复 |
| 4 | A/B 访问对方主页并关注 | 沿用已有个人主页、关注关系，无额外好友申请 |
| 5 | B 回复“关于暴力的讨论 002” | B 显示待审；A 暂时看不到这条回信 |
| 6 | 审核员通过该回信；A 刷新 | A 才能看见，收到通用回信通知 |
| 7 | A 投含站外链接的瓶子 | 留在待审队列，B 捡不到；拒绝后也不会送达 |
| 8 | B 屏蔽 A；A 再回信 | 回信失败；B 不会再匹配到 A 的新瓶子 |
| 9 | B 举报已经领取的瓶子 | 整段对话关闭并回到待审，审核员看见举报来源 |
| 10 | 退出登录后直接打开瓶子链接；换第三个普通账号请求 API | 未登录不能读取；非参与者得到 404/403，不泄露正文 |
| 11 | 手机上打开、输入长文、刷新、结束对话 | 无横向溢出；历史保留；结束后不能继续回信 |

步骤 7 随机领取时如还有别的已通过瓶子，B 可能捡到它们。要验证“捡不到
待审内容”，请根据时间戳核对返回内容，不把“捡到其他瓶子”当作审核失败。

### 如果使用 Vercel

当前 Express 后端依赖可写且持久化的 SQLite 文件；Vercel Functions 的临时文件
系统不能作为这套数据库的存储位置。因此 Vercel 可托管测试前端，构建命令为
`npm run build:web`（海外界面为 `npm run build:web:overseas`），输出目录为
`dist/frontend`，但测试 API 仍需部署到具备持久磁盘的服务，例如上面的 Docker
测试栈。通过同源 `/api/` 反向代理连接测试后端，并为测试前端域名配置 Cookie、
可信来源和 SPA 路由回退。海外私密翻译需要再代理对应的离线翻译服务。

不要把正式 API 用作 Vercel 测试前端的上游，否则账号与瓶子仍会写进正式库。
如果一定要把整个后端也放到无状态平台，需要先单独设计数据库迁移，本次未做
这种架构改动。账号、密码和部署 token 不写进仓库或聊天；使用平台授权或安全
环境配置提供部署访问。

## 提交结果未知与安全重试

投瓶和回信表单在提交前生成随机 UUID `requestId`。服务端按登录账号和该标识
记录成功回执，并以正文、界面语言、操作类型及所属瓶子构成的摘要校验请求。
内容、通知和回执在同一个 SQLite immediate 事务内提交；原样重试返回最初的
201 回执，不再创建瓶子/回信或发送通知，也不额外占用写入次数。同一账号用
相同标识换正文、语言或瓶子会收到 409；不同账号的标识互不影响。

回执持久保存在数据库，应用重启后仍有效，账号删除时级联清理。回执只保存
摘要和原成功响应，不复制私密正文。确认旧提交已保存不代表重新开放已结束或
已屏蔽的对话；新提交仍执行原有权限、审核和限流检查。

当前标签页的 `sessionStorage` 仅暂存账号/瓶子作用域、随机标识与内容摘要。
原文完全相同且界面语言不变时重试复用标识；刷新后重新填入同一草稿也可复用。
正文草稿仍只在页面内存，不承诺刷新后保留；浏览器不允许存储时，同页重试
仍可去重。修改正文/语言或成功后主动再发送会生成新标识，视为新提交。
旧 API 客户端可以不带标识，保持兼容，但这类提交不提供重试去重保障。

网络中断或网关错误时，中文/日文/英文界面提示结果尚未确认、内容可能已保存，
引导查看列表/收信，并保留草稿。若 POST 已明确成功、只是后续读取失败，
则显示“已保存，无需重新发送”。普通读取失败使用本地化网络提示，保留已有正文。
