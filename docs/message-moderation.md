# 留言、评论与回复审核

广场留言、文章评论、回复以及用户编辑统一调用
`backend/services/message-moderation.js`。普通文本直接发布；关键词和站外链接
进入人工审核；活动标记、危险协议以及格式/长度无效的内容拒绝保存。

外链识别对无协议的候选域名检查真实顶级域，避免把中文句号连接的普通句子或
颜文字转换成 Punycode 后误报。`backend/data/domain-tlds.json` 是
[IANA 根区顶级域列表](https://data.iana.org/TLD/tlds-alpha-by-domain.txt) 的本地快照，
更新时保留来源和版本。审核请求不查询 DNS，也不调用外部服务。
显式 URL、IP 地址及保留用途域名仍接受外链检查；协议混淆、全角字符、中文域名、
伪造站内域名后缀和用户信息部分仍按真实主机检查。检查过程不改变保存的原文。

提交接口返回 `moderation: { status, reasons: [{ code, message }], nextStep }`，
同时保留原有 `message` 和 `data.status` 供旧客户端使用。待审记录已保存但不公开；
拒绝时不写入数据库且前端保留草稿。原因提示在表单附近持续显示，不仅显示短暂 toast。

`GET /api/messages/mine` 仅向当前登录用户返回待审原因，响应不缓存。
旧记录没有历史原因快照，因此此处明确标注“按当前审核规则说明”，不把重新计算
当作历史审核记录，也不自动发布旧的待审内容。用户修改后会重新审核；管理员的
人工确认、外链确认和并发审核保护仍按原流程执行。

验证：`tests/message-moderation.test.js` 覆盖真实接口及用户提供的假期原文；
`tests/e2e/message-moderation-feedback.spec.js` 覆盖手机端发布、拒绝保留草稿、
留言/评论/回复原因、用户中心回读和编辑后重审。

## 管理员审核邮件提醒

在 **Terminal → 通知设置 → 我的审核提醒** 中开启「待审核留言邮件提醒」，然后保存。

- `admin` 和 `super_admin` 各自设置，默认关闭。通过网站登录的管理员和后台登录的管理员使用同一账号偏好。
- 只发送到当前账号绑定的真实邮箱；系统占位邮箱不可用。页面显示接收邮箱和邮件服务是否已配置。需要服务器已有 SMTP 通道才会实际发信。
- 新留言、文章评论、回复进入人工审核，以及已公开内容被修改后重新进入审核时，会向所有 `admin` / `super_admin` 生成站内审核提醒，包括邮件关闭或未绑定邮箱的管理员；只有开启个人邮件开关且邮箱可用的管理员才会异步收到邮件。邮件包含审核原因和后台入口，不在邮件中展开整段未审核原文。
- 已直接通过或直接拒绝的提交不发审核提醒。不会补发开启前的历史积压；持续待审核的编辑不重复提醒。同一条内容、同一内容版本、同一接收人通过数据库通知记录去重，进程重启不会重发。
- 发送前再次检查账号角色、个人开关和内容审核状态。已取消订阅、失去管理员身份、内容已通过或已删除时，不再发信。
- 邮件沿用现有异步 SMTP 发送方式；失败只记服务端日志，站内提醒保留，不影响内容提交，不会自动反复重试。SMTP 配置状态不代表收件服务器已投递成功。
- 原有全站评论、点赞、异地登录邮件开关仍仅由后台 `super_admin` 管理。

接口：`GET/POST /api/admin/notification-preferences`（后台会话）或 `/api/moderation/notification-preferences`（网站管理员会话）。POST 只接受布尔值 `emailNotifyModeration`，不能指定他人的账号或收件地址。个人偏好复用 `site_settings` 的私有账号键，不需要数据库迁移或新增依赖，不向公开配置或全站配置响应返回这些键。

相关验证：`tests/email-notification-api.test.js` 覆盖角色隔离、收件资格、各类提交、重复调用、状态变化和发送失败；`tests/mailer-template.test.js` 验证邮件模板；`tests/e2e/terminal-notification-preferences.spec.js` 验证两种登录方式和开关刷新持久化。
