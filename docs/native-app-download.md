# Native app download page

- Public route: `/download`; reachable directly from the header's App download button on desktop and mobile, as well as the Space navigation group and navigation search.
- The page uses the existing seasonal theme, shared navigation and Chinese, English and Japanese copy. It suggests the current device's platform and labels CPU architecture, portable packages, unsigned iOS and unsigned HarmonyOS HAP packages explicitly.
- Installer links go directly to `github.com/redchenk/tsukuyomi-space-app/releases/download/...`. There is no download API, CDN mirror, blob fetch or backend installer proxy.
- The public `/api/app/releases` endpoint fetches only release metadata from the fixed official GitHub repository. Requests share a 5-minute server cache, a 6-second timeout and a 1 MiB response limit; concurrent refreshes are coalesced. Download links are checked against the repository, tag and expected asset filename. Drafts and incomplete releases are ignored.
- The page automatically loads the newest complete version, including beta releases. Stable and beta selectors remain available when both exist. It checks again every 5 minutes while visible and when returning to the tab. Visitors do not need direct browser access to the GitHub API; installers still download from GitHub.
- Successful checks are atomically saved to `data/cache/native-app-release.json`. If GitHub is unavailable or rate-limited, the last successful release survives a server restart; a first-run failure uses `shared/native-app-release.json`. Failed checks back off for 1 minute, keep working links, and display the failure state honestly.
- Publishing an app Release updates downloads automatically on the next cache refresh, without rebuilding or redeploying the website. `npm run sync:app-release` is now optional maintenance of the initial offline fallback; it does not download installers.
- The backend renders public installation guidance and direct download links without JavaScript. The overseas public-route allowlist and SEO copy include `/download`.

Validation: `tests/frontend-native-download.test.cjs` covers selection, link validation, platform suggestions, metadata limits/cache/cancellation and locale coverage. `tests/native-app-release.test.js` checks the public endpoint, concurrent refreshes, durable cache, outage/backoff and invalid upstream responses. `tests/e2e/native-app-download.spec.js` checks live page updates and channel selection. `tests/seo-geo.test.js` checks public HTML, direct GitHub assets and sitemap entry. Local fixtures use `APP_RELEASES_OFFLINE=true` to avoid external network dependencies.

HarmonyOS downloads use the versionCode-bearing `tsukuyomi-space-<version>-<build>-ohos-arm64-unsigned.hap` filename from the selected Release. They are optional: older Releases remain usable without OHOS, and each channel only shows its own package. A HAP is exposed only with one matching uploaded official asset, a SHA-256 digest, `OHOS-INSTALL.md` and `OHOS-SHA256SUMS.txt`. Same-tag supplements survive older persisted metadata. HarmonyOS/OpenHarmony device identifiers take priority over Android/Linux suggestions.

The card states HarmonyOS 6.0.2 / API 22 or later, ARM64 and mandatory self-signing through DevEco Studio. It links the platform-specific guide/checksums and retains the physical-device acceptance limitation from the official installation guide. Chinese, English, Japanese and no-JavaScript public HTML include these requirements. No signed installer or app-store availability is implied.
