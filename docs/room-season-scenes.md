# Room 四季昼夜背景

2026-10-06：用户确认湖畔小屋美术方案后接入本地项目。没有后端、数据库、模型、音乐或服务器配置改动。

## 使用与时间规则

- Room 背景跟随全站季节主题。自动模式按设备本地日期与所选半球决定季节；手动模式复用顶部菜单中的季节选择。
- 白天为设备本地时间 06:00（含）到 18:00（不含），其他时间为夜晚。房间的日照独立于界面的浅色／暗色选择。
- 房间右上角的小屋按钮显示对应季节及太阳／月亮图标，展开可查看时间规则和现有天气信息。
- 日期改变、跨标签季节偏好同步、后台恢复及设备时间改变后的窗口激活均重新核对。房间分享仍保留既有天气上下文，背景跟随查看者的季节偏好与本地时间。
- 当前只有白天和夜晚两档，不生成独立清晨／黄昏图片，不根据 IP 或天气 API 推断日照。

## 资源与性能

八张图在 `src/frontend/assets/room/lakeside-v1/`。四季各有白天、夜晚一张，统一 1672 × 941，WebP quality 90 保留原尺寸。全套 1,977,030 字节，最大单张 282,398 字节；原图与确认预览在 `output/imagegen/room-lakeside-v1/`。

使用 Vite 的内容哈希 URL，图片映射只随 Room 路由加载。URL 导入不会下载所有图片；首次只请求当前场景，季节或昼夜改变时才加载对应的新图片。新图解码完成前保留当前场景，失败则保留上一张；快速连续选择通过取消与结果校验防止旧请求覆盖新场景。没有整套预加载、每帧逻辑、外部服务或新增后台进程。

Room 可见时只有一个定时器，直接休眠到下一个 06:00／18:00 边界。后台暂停，恢复时立即核对，离开路由移除定时器与事件监听。既有全站午夜季节定时器继续工作。时间按本地日历计算，处理跨日与夏令时。

电脑舞台和手机全屏背景使用同一个场景变量，保留既有布局、模型尺寸、画布渲染预算、聊天气泡、输入法处理和按钮圆角。减轻旧房间遮罩，并为白天／夜晚设置背景上文字的对比色。

`manifest.json` 记录压缩资源及原图的尺寸、字节数、SHA-256；`prompts.json` 保存内置 imagegen 的完整提示词及参考图用途。

## 发布与回滚

发布沿用项目现有轻量流程，本地构建两站产物，将构建资源与代码一起发布，不在服务器安装依赖或构建。`prepare` 显式传入 `--retire-room-artwork` 才放行上述两个文件的删除；路径和原图 SHA-256 固定在发布工具中，不能传入其他媒体路径。Git 原文件和服务器现有文件均须符合原始哈希，只允许删除，不允许替换；服务器文件已不存在时记录为空。准备阶段备份原图，激活与回滚前复核原图、备份和路径，拒绝符号链接、人工改图或更新的发布。其余受保护资源仍完整核验，不能对服务器 `assets/` 或模型目录批量删除。该参数在清理完成后的发布只核对这两个路径仍为空，不扩大可清理范围。

回滚使用发布备份目录的 `release.py rollback --state <备份目录>`，恢复上一版本前端及准备时存在的旧图像，保持季节偏好、用户资料、模型和音乐不变；无需数据库迁移。沿用现有发布流程刷新 API 进程读取的前端入口。

发布安全回归额外覆盖显式放行、其他媒体拒绝、图像替换拒绝、原图哈希不符、人工编辑、符号链接、备份损坏、较新文件拒绝覆盖，以及两站删除／回滚和缺失文件处理。
