# 本地记忆验收记录（2026-10-03）

测试环境：国内实际 Ubuntu 24.04 主机、2 核 / MemTotal 3499 MiB；固定哈希 BGE ONNX 权重、onnxruntime 1.22.1、sqlite-vec 0.1.6、Mem0 3.3.0。所有样例均为模拟数据，没有导出用户私有聊天。

## 真实模型与索引

- 完整来源“花生会让我起红疹。”被推到近期 120 条兜底窗口之外后，提问“零食里哪些食材不能吃”仍通过真实 Mem0 原生存储适配器及 sqlite-vec 召回。健康事项的重要度 0.94、置信度 0.88，并保存对应原话。
- 另一随机账号的相同提问无法读取这些记忆。手动改为“我现在需要避免腰果”后，旧花生向量立即被来源摘要核验排除，未等待重建。
- 真实语义分类识别感谢并增加互动进度；小说引述“我叫大卫”降到 0.15；“今天很难过，不想聊天”不加分、不扣分。
- 五种样例首次分类约 986 ms（含样例向量初始化），其余约 32–43 ms。完整检索验收脚本的多次读取与编辑校验合计约 332 ms；这不是单次查询的并发吞吐保证。
- 向量服务启动峰值约 247 MiB，完成推理后约 256 MiB。生成式 Qwen 0.6B 的实测约 0.5 token/s，不采用该方案，也不把其权重放入正式运行时清单。

## 内存隔离

临时验证进程放在同一个后台 slice 内，额外施加 32 MiB 的单进程硬限制，然后申请 128 MiB。systemd 返回 `Result=oom-kill`；网站 API 在测试前、测试中、测试后共 60 次请求全部成功，测得 p95 分别约 125/46/28 ms。此项验证内核隔离及当前网站可用性，不代表任意并发量或其他进程也能保证同样延迟。

正式方案总后台硬上限为 640 MiB、swap 为 0；网站进程位于该 slice 外。模型接口为权限 `0600` 的 Unix socket，无公开监听端口。运行前同时检查 MemAvailable 768 MiB 保留量及 CPU 负载。
