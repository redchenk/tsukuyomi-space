# Room 长期记忆 HTTP 414 修复

## 原因与范围

2026-10-23 核验发现，网页把聊天文本以及重试快照、排除轮次放进 GET 查询参数。中文 URL 编码后显著变长，超过源站或网络中间层的 URI 限制。正常检索和备用检索沿用同样的长 URL，因此备用路径也不能恢复。

只查看错误状态和请求长度的日志聚合：当前及上一份源站日志中有 33 条 `/api/room/memory`、11 条 `/api/room/persona-memory` 的 414；被拒绝的请求行长度达到 8188 字节。公网合成请求中，20 个中文字得到正常的未登录 401，3000 个中文字的 URL 约 27 KB，得到 414。没有读取或导出用户聊天内容。此证据确认 URI 长度问题，不能据此断言某个运营商或 iPhone 硬件有问题。

## 改动

- 网页统一通过 `POST /api/room/memory/search`、`POST /api/room/persona-memory/search` 发送 JSON，覆盖聊天主检索、备用检索、重试快照、角色资料和设置页管理搜索。
- 旧 GET 路由保留，兼容旧页面和原生 App；现有 POST `/memory` 仍用于保存。
- 保留当前账号范围、来源选择、召回数量、实时删除/编辑验证、取消信号、禁止缓存和来源校验。
- 新接口校验 JSON 类型、查询长度及快照/排除列表。查询上限沿用现有聊天文本上限 200000 字符；全局请求体上限继续生效。
- 不调整 Nginx URI 上限，不清理用户本地存储，不迁移或清空记忆数据。

## 验证

- 68 项相关单元及接口测试：长中文、主检索与来源回退、分页、快照、编辑/删除、账号隔离、401/403、非法参数、原有 Mem0 与本地记忆行为。
- 浏览器覆盖：WebKit iPhone 11 配置与 Chromium，在拦截超过 2048 字符 URL 的测试代理下，用真实隔离数据库检索长中文并注入模型请求；仅模型回复使用测试桩。覆盖设置页搜索和 503 后的备用检索。
- 既有浏览器用例继续检查重载、游客持久化、账号隔离、12/20 条记忆配置与重生成。测试配置补全模拟模型参数，并等待启动遮罩消失和新回复完成，避免读取旧一轮结果。
- 前端生产构建通过。全站前端测试 485/488 通过；未修改基线独立复现相同 3 项失败：邮件管理页面缺少翻译，以及两项文章点赞测试的模拟上下文缺少 `getSession`。这次不修改这些无关功能。

WebKit 设备配置是浏览器回归，不等于真实 iPhone 11 蜂窝网络验收。上线后关闭旧 Room 标签再重新打开即可获取新脚本；无需清空网站数据。旧 GET 长请求仍可能返回 414，修复点是新版网页不再发出该请求。
