# 自动邮件设计与验证

网站全部自动邮件共用 `backend/services/mail-design.js` 的月白樱粉模板：月夜蓝文字、圆角白色卡片、八千代樱花横幅、樱粉内容区和胶囊按钮。邮件内容由 `backend/services/mailer.js` 按用途填写。

## 覆盖类型

| 类型 | 必须保留的内容 | 操作 |
| --- | --- | --- |
| 注册验证码 | 验证码、实际有效期、注册说明 | 返回月读空间 |
| 登录验证码 | 验证码、实际有效期、登录说明 | 返回月读空间 |
| 绑定邮箱验证码 | 验证码、实际有效期、绑定说明 | 返回月读空间 |
| 重设密码验证码 | 验证码、实际有效期、安全提示 | 返回月读空间 |
| 评论或回复 | 标题、发送者、内容摘要 | 原有讨论链接或站内信 |
| 点赞 | 标题、发送者、动态摘要 | 原有内容链接或站内信 |
| 待审核内容 | 内容摘要、审核说明、关闭提醒的入口说明 | Terminal 审核页面 |
| 异地登录 | 地点、设备、IP、UTC+8 时间、安全提示 | 用户中心 |
| Terminal 自定义邮件 | 管理员填写的主题、完整正文、分段与换行 | 可选本站按钮 |

发送权限、开关、收件资格、通知去重、验证码有效期及 SMTP/TLS 流程继续使用现有机制。用户通过邮箱功能自行撰写的邮件保留其原始内容。

## 图片、兼容性与资源预算

- 两张固定素材在 `backend/services/mail-assets/`，随后端和 Docker 镜像发布。文件首次使用时读取并缓存；logo 限制为 16 KiB，横幅限制为 36 KiB。尺寸和压缩在发布前处理，发送时不进行图像处理。
- 顶层 MIME 为 `multipart/alternative`，包括完整纯文本版本与一个 `multipart/related` HTML 版本。PNG 标志及 JPEG 横幅通过 `Content-ID` 和 `Content-Disposition: inline` 引用。
- 收件人不需要连接网站获取图片，也没有第三方图片、跟踪像素或带验证码的远程图片 URL。
- 验证码、通知正文、有效期与操作链接使用真实文本。屏蔽图片或只查看纯文本仍能完成操作。
- 模板使用表格布局和内联颜色，不依赖 JavaScript、SVG、Web 字体、CSS 变量或网页样式文件。所有类型固定使用浅色背景，不跟随系统切换暗色；支持窄屏媒体查询，并为忽略媒体查询的客户端保留流式宽度与可读基础样式。
- 旧 Outlook 使用条件表格约束宽度；现代邮箱可显示圆角。不同邮箱仍可能改写样式或把内嵌图片列在附件中，可用 EML 验证实际客户端。
- 横幅为 640 × 256，logo 为 96 × 96，两张素材合计约 45.6 KiB。8 类完整示例邮件为 75.9–78.1 KiB，v1 为 176.2–178.4 KiB，减少约 56–57%；回归预算收紧至 96 KiB。HTML 本身约 10 KiB。动态内容继续做 HTML 转义、长度限制和同站链接校验。

## 本地预览

```sh
npm run preview:emails
python3 -m http.server 4202 --bind 127.0.0.1 --directory .codex_tmp/email-preview
```

打开 `http://127.0.0.1:4202/` 可切换 8 类邮件。预览工具从实际 MIME 消息解析 HTML 和内嵌图片，并提供 `.eml` 下载；仅使用示例账号、示例验证码，不调用 SMTP。可选输出目录：`node scripts/preview-site-emails.js <目录>`。

## 验证和发布

```sh
npm run check:mail
node --test tests/mailer-template.test.js tests/mail.test.js tests/email-notification-api.test.js tests/login-location-alert.test.js
```

`mailer-template.test.js` 检查动态文本转义、同站操作链接、邮件头注入、未知用途回退、纯文本备用内容、嵌套 MIME、两张图片的 CID/字节完整性，以及 96 KiB 的示例消息预算。发布前还应检查 8 类模板在桌面、320px 手机、系统暗色但邮件仍为浅色，以及屏蔽图片/移除头部样式后的渲染。体积减少可以降低邮件传输和图片解码成本；实际打开耗时仍受邮箱客户端及网络影响，不以本地预览耗时代替真实收件测量。

上述自动邮件模板不需要迁移、安装依赖、公开素材路由或新增配置。回滚恢复上一版代码及模板。已经发送到邮箱中的邮件保持原来的内容。

## Terminal 自定义发送

超级管理员在 `/terminal?panel=mail` 打开发送邮件，按昵称、用户名、邮箱或用户 ID 搜索，并按用户角色筛选。可以跨页勾选单个或多个用户，也可群发给全部匹配用户（包含其他分页）；清空筛选即选择全部符合条件的用户。仅使用已有有效邮箱，排除 OAuth/管理员占位邮箱，相同邮箱在一批内去重，单批最多 10000 个邮箱。

主题最多 120 字符、正文最多 10000 字符，按纯文本转义并保留换行，按钮链接可选且限本站。预览直接使用真实邮件模板和内嵌图片；点击确认后使用预览时固定的内容与名单，预览有效期 30 分钟。每封邮件只有一个收件人。重复确认同一批次不会重新发送。

迁移 `050_create_mail_campaigns` 新增发送批次与收件结果表。API 进程启动队列，每个进程每次处理一封邮件，约每秒开始一次；离开页面后继续执行。任务通过数据库事务认领，重启保留待发送记录。已删除账号或已变更邮箱会跳过；中断超过五分钟的发送记为“待核实”，不自动重发。可停止未开始的邮件，正在执行的邮件会记录最终结果。

发送记录显示最近 30 批及逐邮箱结果。“已提交”只表示 SMTP 服务接受，不证明收件箱送达；拒收记为失败，网络结果不明确记为待核实。群发使用现有 SMTP 配置，不依赖评论/点赞提醒开关，也不会更改用户的自动通知偏好。

验证：`node --test tests/mail-campaigns.test.js tests/mailer-template.test.js tests/email-notification-api.test.js`，以及 `npx playwright test tests/e2e/terminal-mail.spec.js`。浏览器夹具使用临时数据库和模拟邮件通道，不会向真实邮箱发送。上线前备份数据库，按明确文件清单部署并重载 API，使迁移和队列启动；回滚代码时保留新增表及发送记录，避免重复发送。
