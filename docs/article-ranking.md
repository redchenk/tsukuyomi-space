# 文章成长、有效阅读与每日推荐

主舞台默认「精选优先」，还可以选择「每日推荐」和「最新优先」。精选先展示当前快照的混排推荐，再展示其余文章；每日推荐只展示当前快照最多 12 篇入选文章。最新严格按首次发布时间倒序，编辑文章不会刷新发布时间。人工置顶保留「编辑推荐」标记，在推荐选择中只提供少量加分，不永久占据首位。旧版未指定 sort 的 API 保留置顶兼容排序。

## 作者经验

- 新增有效阅读：作者 +1 XP。
- 每个账号首次点赞一篇文章：作者 +2 XP。
- 每个账号首次收藏一篇文章：作者 +5 XP。
- 作者自己的操作不奖励。点赞/收藏可以取消，但取消再操作不会再发经验；互动与经验账目在同一数据库事务中提交。
- Growth 页面展示三类累计经验、总额、补发数及最近记录，既有签到和任务经验保留。

037 为独立的加表迁移。新版应用第一次启动时，在一个事务中补发当时全部现存文章（包括曾公开后撤回的文章）的历史阅读量、有效点赞及收藏对应的经验，并保存完成凭据；反复重启不会重复补发。现存历史阅读数完整保留，因旧系统未保存阅读身份，无法追溯去重。作者自赞/自收藏不计入补发；已删除文章或已取消的历史互动没有可靠记录，不能凭空恢复。详情见 [迁移说明](article-engagement-migration.md)。

## 阅读防刷

详情 GET、SSR、预加载和接口重试都不增加阅读数。浏览器在文章前台连续显示 12 秒后提交服务器签名凭据；切到后台、离开文章会停止计时。服务器验证文章、账号、设备、凭据时效和最短间隔，并限制提交频率。

设备使用服务器随机生成、HMAC 签名的 HttpOnly/SameSite Cookie，不采集硬件指纹。对同一文章，账号或设备任一身份已经阅读过，就不再计数（不限于当天）；从游客登录、换设备登录时会合并已观察到的身份。作者自己的设备也会标记，防止退出账号后重复计数。匿名请求另有网络地址与 User-Agent 的带密钥摘要按 UTC+8 自然日兜底，防止简单清除 Cookie 后刷新；不会仅因共用网络而合并两个不同的登录读者。数据库不保存该用途的原始 IP。

这能阻止重复点击、刷新、多标签页、常见 Cookie 重置及反复点赞收藏，不能证明物理设备身份，也不能彻底阻止主动换网络、设备和多账号的攻击。不会把历史原始点击伪称为已验证独立读者。阅读与经验一起原子提交，重试不会多计。

## 旧版每日推荐（历史快照兼容）

基础评分仍为内容 40、阅读 15、点赞 20、收藏 20、新鲜度 5。正文有效深度、非重复段落、媒体和组织结构参与内容评分；对数饱和和平滑比例限制纯点击或少量互动的影响。隐藏 HTML、重复堆字、封面和自填阅读时长不加分。作者自赞和自收藏不参与推荐评分。

按 UTC+8 日期生成并持久化当天榜单。每组 6 个推荐位置包含 3 个综合质量位置、2 个最久未获推荐的位置、1 个近 14 天新作位置（没有新作时回退到质量候选）。每日确定性扰动及近期推荐降权避免一直固定同序；有足够不同作者时，每位作者最多占 2 个位置。内容分至少 6 才进入每日推荐候选，保留短篇和图片作品的机会。任务/打卡/签到分类和低内容分的相应占位标题不进每日推荐，在精选剩余列表中后置；仍可通过最新、分类及搜索找到。

同日顺序固定，互动计数实时更新、排序分次日更新。当天新发布的文章立即出现在最新和精选后续列表，次日参与推荐；这样翻页不会因为中途发布或点赞而跳位、重复。分类、搜索在同一份当天顺序上过滤，不改变其他页面次序。每日推荐不足 12 篇时显示实际候选数，不用空文补满。

逐篇提取正文特征（非 block 最多前 200,000 字符；block 完整解析后限制可见文本），只在内存保留紧凑评分字段；内容特征缓存上限 256。当前快照保留最近 3 个日期，每篇文章另保存一个最近推荐日期用于公平轮换，无需后台常驻计算、外部模型或新增依赖。

## 原生发现推荐 v1（2026-10-21）

主舞台默认改为「精选优先」，SSR 与浏览器一致。「最新优先」仍严格按首次发布时间排序；文章 ID、slug、canonical、公开状态和正文保持原有规则。月契成长的轮换任务改为访问 `/stage`（20 XP），进入实际页面即提交已登录账号的访问，不从预加载或文章列表 GET 发经验。服务器只接受当前分配的任务，每天一次；旧 `daily_article_publish` 的历史经验及当天完成状态保留，不允许同一天再领取访问奖励。

推荐使用 Node.js + SQLite 原生服务，无外部模型、向量服务或机器学习平台依赖。每六个位置为「质量、新作、质量、低曝光潜力、优质旧文、探索」。新作优先窗口七天，以累计 30 次已确认曝光作为初始探索目标；这是排序倾向，不承诺流量或固定次数。旧文位优先选择发布超过三十天的合格作品，长期内容分不使用强时间衰减。有足够候选时，每位作者最多两个位置，分类采用软配额；供给不足时逐步放宽，避免空位。探索使用以快照为种子的 Beta(reads+2, impressions-reads+18) 采样，不依赖进程随机状态。

现有正文结构、有效深度、独立媒体和真实互动继续作为基础信号；长度和排版只是内容质量的近似，不能等同于写作价值。具有基本独立内容的短篇也有资格进入探索。新数据评分按推荐来源和展示位置分组，使用各组实际反馈率及 20 次曝光先验作平滑，再比较文章的曝光后有效阅读、首次点赞和首次收藏。反馈影响随样本量增长，最近七天连续获得真实曝光的作品额外冷却，历史阅读量绝不伪装成历史曝光。旧文的正文价值和现有互动不会因为上线新计量被清零。

卡片采用 IntersectionObserver：至少一半可见、前台连续一秒才批量提交曝光。个人签名凭据通过独立的 `POST /api/articles/discovery/session` 取得，不放进公开列表缓存、URL 或分享链接。服务器重新取对应页，签入真实文章 ID、展示位置、来源、账号和现有阅读设备标识；客户端不能自行指定排名位置或曝光数量。凭据二十分钟有效，服务器校验最短时间；每账号/设备、每文章、每天去重，匿名还保留带密钥的网络摘要兜底。作者自己的曝光不计入。该机制防止常见刷新/重放，不能证明物理设备或完全阻止伪造可见性与多账号攻击。

曝光后的十二秒有效阅读沿用现有阅读凭据、防刷和 XP 规则，通过同源 sessionStorage 中的短期归因凭据联系曝光。重复阅读不会增加历史阅读数或经验；推荐反馈同一天至多一次。点赞和收藏仍只按首次有效互动奖励及归因。设备 Cookie 是原有随机、签名的 HttpOnly Cookie，不采集硬件指纹；数据库只保存带密钥摘要。逐次去重凭据保留七天；匿名按日聚合的数据保留用于后续评估。

排名每十五分钟生成一份快照；文章创建/编辑、置顶或分类整理使下次首次访问获取新快照，因此合格的新作当天就能进入预留位。分页一直携带同一快照 ID，不因期间的新作或互动发生重复、漏项；返回相同列表保留其上下文。快照保存三天，过期后回到第一页刷新。旧版每日快照表保留为兼容数据，新的列表以 `recommendationSnapshot`、`recommendationEngine: native-v1` 为服务边界，未来更换引擎无需改变文章与阅读协议。

管理员可使用 `GET /api/articles/discovery/report?days=7` 查看真实曝光、曝光后有效阅读率、新作/三十天以上旧文曝光、独立作者数量和来源/位置分布；不返回设备摘要或阅读者身份。首次曝光延迟只基于保留期内的真实记录，不回填未知历史。

## 任务帖归类和安全回填

`article-content-policy.js` 根据明确的任务/签到/打卡意图、编辑器占位正文、单字符或重复字符识别任务帖。正常教程中提到「任务」不会因此改类；图片、媒体和下载资源不会仅因配文短被判为空文；标题本身提出明确问题的短讨论保留。新发布和编辑的匹配文章自动归到「任务」。任务帖不进入发现推荐位、在精选剩余列表后置，推荐分以基础分的 5% 展示；在任务分类、搜索和最新列表仍可访问。首页的新鲜事优先显示正常文章。

历史整理必须先运行只读计划并逐项审阅，再显式应用：

```sh
node scripts/classify-task-articles.js --database /path/site.db --plan /private/plan.json
node scripts/classify-task-articles.js --database /path/site.db --apply /private/plan.json --receipt /private/receipt.json
```

应用前再次核对文章正文与标题指纹，整批事务更新；过时计划拒绝应用。仅修改 `category`，保留 ID、链接、正文、作者、状态、发布时间、更新时间、互动和已发经验。计划和回执保留原分类，可按 ID 与当前分类/指纹核对后恢复；不得用整库覆盖回滚在线用户的新数据。
